# Архитектура демонстрационного прототипа

## Компоненты

### Frontend

`frontend/src/App.tsx` реализует React-интерфейс для выбора режима и сценария, настройки модели, проигрывания демонстрации и просмотра результатов. Общие структуры API описаны в `frontend/src/types.ts`. Vite обслуживает frontend при разработке, а production-сборка выводится в `frontend/dist`.

### Backend

`backend/app/main.py` создаёт FastAPI-приложение, валидирует запрос симуляции через Pydantic, публикует API и раздаёт production-сборку frontend. `backend/app/adaptive_control.py` содержит учёт подтверждённых ID, плотность, приоритет и интерфейс фазового адаптера с проверяемой виртуальной реализацией. `backend/app/simulation.py` содержит параметры и синтетические сценарии. `backend/app/video_episode.py` загружает и проверяет CV JSON; записи без ID и геометрии работают только с резервным циклом.

### Пользовательский поток симулятора

Вкладка «Симулятор» передаёт `TrafficProfile` в `POST /api/simulate` при `scenario_id=custom`. Backend детерминированно распределяет прибытия машин и пешеходов по секундам двухминутного эпизода, применяя коэффициенты времени суток и типа дня. Затем контроллер рассчитывает фазы, события и показатели. Каждый кадр содержит количество новых автомобилей и пешеходов.

Frontend строит по кадрам траектории на одной прямой двусторонней дороге с двумя полосами в каждом направлении, единственным пешеходным переходом и островком безопасности. Все четыре полосы получают один сигнал; во время зелёной автомобильной фазы машины едут навстречу друг другу по центрам размеченных полос, а перед запрещающим сигналом останавливаются у стоп-линии. Поступления автомобилей за одну секунду равномерно распределяются внутри этой секунды; число машин остаётся равным ответу API. Пешеходы ждут на противоположных тротуарах в распределённых точках, подходят к зебре без скачка, начинают переход с небольшим разбросом по времени и движутся с разной скоростью. Придорожный знак каждого подхода расположен перед автомобильным светофором по ходу движения, на той же линии тротуара. Во время `all_red_to_vehicle` все сигналы остаются запрещающими; машины трогаются только на зелёный. Дистанция остановки учитывает длину кузова. Движение рассчитывается с шагом 0,1 секунды и интерполируется при отрисовке. Пешеход может начать переход во время `pedestrian_walk` и завершить его в течение `pedestrian_clearance`; позже начинать переход нельзя. Материалы, освещение и объёмные элементы создают вид дорожного макета; двенадцать светильников освещают проезжую часть в вечернем и ночном режимах. Две модели камер закреплены на мачтах подвесных знаков. Их координаты и точки наведения заданы в `cameraMounts`: каждая камера направлена через переход к противоположному тротуару. Переключатель в `ThreeRoadScene.tsx` выбирает общий вид или одну из двух виртуальных камер; все ракурсы показывают один и тот же текущий кадр симуляции, а не реальные видеопотоки. Траектории и очереди визуальные и не участвуют в расчёте контроллера.

### Видеоданные

`video_episode.py` содержит реестр заранее подготовленных видеоэпизодов. Каждый эпизод связывает MP4 с JSON посекундных наблюдений и публикует собственный `video_url`. Текущая пара находится в `video_and_json`: JSON содержит счётчики, а оптимизированный MP4 служит визуальным сопровождением. Координат, детекций, треков объектов и обработки изображения во время работы веб-приложения нет.

## Жизненный цикл запроса симуляции

1. Frontend отправляет идентификатор сценария и настройки в `POST /api/simulate`.
2. `main.py` выбирает обработчик: синтетическую модель `simulate` или `simulate_video`.
3. Модель читает входы на каждом временном шаге, обновляет фазу, накапливает события и метрики.
4. Backend возвращает кадры, журнал событий, сводную статистику, доступность проезда и, для видео, baseline.
5. Frontend воспроизводит временную шкалу, показывает состояние перехода и сравнение.

## Фазы и правила переходов

Порядок фаз цикличен и не может быть пропущен:

```text
vehicle_green → vehicle_yellow → all_red_to_pedestrian → pedestrian_walk
       ↑                                                         ↓
all_red_to_vehicle ← pedestrian_clearance ←──────────────────────┘
```

В адаптивном режиме запрос пешеходов ожидает выполнения минимальной длительности зелёного для автомобилей. Считаются уникальные ID в зонах ожидания и машины в размеченном участке. Запрос фиксируется при `N_waiting/(1+k/k_ref) + wait_s/t_max_s >= 1`; сглаженная плотность `k` определяется только по одновременной занятости участка. Короткие пропуски ID не обнуляют ожидание. Запрос обслуживается при начале `pedestrian_walk`; вновь пришедшие люди учитываются отдельно.

При недоступном наблюдении или устаревшей фазе включается фиксированный резервный цикл. Ручной режим использует пользовательский план фаз. Длительности и геометрию задают `Config` и `PhasePlan`; реальный адаптер оборудования ещё не подключён.

## Контракт наблюдений

Подробная схема находится в `CV_DATA_FORMAT.md`. На текущем этапе это массив односекундных счётчиков: `camera_ok`, `vehicles`, `new_vehicles`, `waiting`, `new_pedestrians`, `on_road`. Когда `camera_ok` равен `false`, числовые значения должны быть `null`, чтобы отсутствие данных не смешивалось с нулевым трафиком.

Модель на видео оценивает транспортный поток по числу новых автомобилей в скользящем окне 30 секунд. Поскольку формат не передаёт индивидуальные ID, геометрию участка и состояние контроллера, адаптивный расчёт на нём отключён. Поле `on_road` служит только для отображения записи; оно не сокращает обязательное время освобождения. Метрики ожидания являются приближёнными.

Метрики `vehicle_green_seconds`, `vehicle_closed_seconds` и `vehicle_green_share` описывают распределение фаз и не выдаются за оценку фактической задержки автомобилей.

## Текущие границы

- CV-инференс выполняется вне этого приложения; backend принимает заранее подготовленные MP4 и JSON.
- Нет потокового подключения устройств или удалённого хранения.
- Наблюдения в демонстрационном JSON подготовлены для показа и не являются ground truth.
- Контрфактическое сравнение циклов на готовом видео является модельной оценкой, поскольку последующие действия участников движения записаны при работе реального светофора.
- Симуляция не учитывает подробную геометрию дороги, дорожные нормы, задержку датчиков или взаимодействие с соседними фазами.
- Расчёты не предназначены для непосредственного управления реальными сигналами.
