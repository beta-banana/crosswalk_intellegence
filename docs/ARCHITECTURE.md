# Архитектура демонстрационного прототипа

## Компоненты

### Frontend

`frontend/src/App.tsx` реализует React-интерфейс для выбора режима и сценария, настройки модели, проигрывания демонстрации и просмотра результатов. Общие структуры API описаны в `frontend/src/types.ts`. Vite обслуживает frontend при разработке, а production-сборка выводится в `frontend/dist`.

### Backend

`backend/app/main.py` создаёт FastAPI-приложение, валидирует запрос симуляции через Pydantic, публикует API и раздаёт production-сборку frontend. `backend/app/simulation.py` содержит модель фаз, параметры и синтетические сценарии. `backend/app/video_episode.py` загружает и проверяет CV JSON, строит потоковые показатели и моделирует результат на видеонаблюдениях.

### Видеоданные

`result_crosswalk.json` содержит посекундные счётчики наблюдения. `result_crosswalk_web.mp4` — облегчённая версия видео для браузера. Backend использует JSON как вход модели, а видео — только как визуальное сопровождение. Координат, детекций, треков объектов и обработки изображения в приложении нет.

## Жизненный цикл запроса симуляции

1. Frontend отправляет идентификатор сценария и настройки в `POST /api/simulate`.
2. `main.py` выбирает обработчик: синтетическую модель `simulate` или `simulate_video`.
3. Модель читает входы на каждом временном шаге, обновляет фазу, накапливает события и метрики.
4. Backend возвращает кадры, журнал событий, сводную статистику и, для видео, baseline.
5. Frontend воспроизводит временную шкалу, показывает состояние перехода и сравнение.

## Фазы и правила переходов

Порядок фаз цикличен и не может быть пропущен:

```text
vehicle_green → warning → all_red_to_ped → pedestrian_green → all_red_to_vehicle
       ↑                                                               │
       └───────────────────────────────────────────────────────────────┘
```

В адаптивном режиме запрос пешеходов ожидает выполнения минимальной длительности зелёного для автомобилей. Далее модель может начать предупреждение при подтверждённом свободном интервале, низком потоке, достижении допустимого времени ожидания или приоритете большой группы. Встроенная модель считает свободной дорогу, если пять секунд подряд нет наблюдаемых машин. Запрос сохраняется до зелёной фазы пешеходов.

При недоступном наблюдении включается фиксированный резервный цикл. Фиксированный baseline нужен для сравнения на одинаковом входе; ручной режим использует пользовательский план фаз. Защитные ограничения полей задаются схемами `Config` и `PhasePlan`.

## Контракт наблюдений

Подробная схема находится в `CV_DATA_FORMAT.md`. На текущем этапе это массив односекундных счётчиков: `camera_ok`, `vehicles`, `new_vehicles`, `waiting`, `new_pedestrians`, `on_road`. Когда `camera_ok` равен `false`, числовые значения должны быть `null`, чтобы отсутствие данных не смешивалось с нулевым трафиком.

Модель на видео оценивает транспортный поток по числу новых автомобилей в скользящем окне 30 секунд. Запрос регистрируется при появлении ожидающих пешеходов; зелёная фаза продлевается, пока `on_road` указывает, что кто-то остаётся на проезжей части. Поскольку формат не передаёт индивидуальные ID и времена прибытия, метрики запросов и ожидания являются приближёнными.

## Текущие границы

- Нет CV-инференса, обработки видеокадров, подключения устройств или удалённого хранения.
- Наблюдения в демонстрационном JSON подготовлены для показа и не являются ground truth.
- Симуляция не учитывает геометрию перекрёстка, дорожные нормы, задержку датчиков или взаимодействие с соседними фазами.
- Расчёты не предназначены для непосредственного управления реальными сигналами.
