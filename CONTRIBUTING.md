# Участие в разработке

Спасибо за интерес к проекту. Сейчас это демонстрационный прототип адаптивного перехода; изменения модели не следует трактовать как готовые рекомендации для реального дорожного объекта.

## Локальная среда

Следуйте разделам «Быстрый запуск» и «Локальная проверка» в [README.md](README.md). Разработка интерфейса ведётся через Vite, API — через FastAPI.

## Pull request

- Используйте отдельную ветку и небольшие, предметные изменения.
- Обновляйте `CV_DATA_FORMAT.md`, если меняются поля или смысл наблюдений.
- Запускайте backend-тесты и production-сборку frontend.
- В pull request опишите мотивацию, ключевые изменения, команды проверки и известные ограничения.
- Для изменений, затрагивающих порядок фаз, защитные интервалы или резервный режим, добавьте сценарии, которые описывают ожидаемое поведение.

## Стиль и границы

- Python: типизируйте публичные функции и сохраняйте валидацию входных данных.
- Frontend: TypeScript/React; сохраняйте разделение типов в `frontend/src/types.ts`.
- Не коммитьте виртуальные окружения, `node_modules`, локальные секреты и исходные большие видео.
- Не представляйте симуляцию или оценочные CV-показания как сертифицированные данные реального перекрёстка.
