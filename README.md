# Умный пешеходный переход

**Версия приложения: 1.1.0** · [История изменений](CHANGELOG.md)

Демонстрационный веб-прототип адаптивного управления пешеходным переходом. Он показывает, как наблюдения о дорожной обстановке могут влиять на переключение фаз светофора: контроллер учитывает поток машин, ожидающих пешеходов, безопасный интервал без машин и доступность камеры.

> **Статус проекта:** прототип для демонстрации и экспериментов. Это не сертифицированный контроллер дорожного светофора. Расписание фаз и результаты на видео смоделированы; приложение не подключено к реальной камере, CV-системе или оборудованию.

## Что умеет приложение

- Показывает демонстрационную видеозапись и синхронные с ней посекундные наблюдения.
- Моделирует состояния цикла: зелёный для машин, предупреждение, защитный интервал, зелёный для пешеходов и интервал перед возвратом автомобилей.
- Сравнивает адаптивное управление с фиксированным циклом на одних и тех же наблюдениях.
- Показывает показатели движения, события, причины смены фаз и оценку времени ожидания.
- Показывает долю времени, когда проезд открыт транспорту, чтобы улучшение для пешеходов не скрывало цену для автомобильного потока.
- Позволяет запускать встроенные сценарии: обычный поток, час пик, большая группа пешеходов, пустая дорога и отказ камеры.
- Даёт менять параметры управления через интерфейс и API.
- Содержит вкладку «Симулятор» с картой в перспективе, схематичным движением машин и пешеходов, настройкой обоих потоков, времени суток, типа дня и фаз, а также автоматическим пересчётом результатов. Настройки симулятора сохраняются в браузере.

### Поток данных

1. Интерфейс запрашивает список сценариев у `GET /api/scenarios`.
2. Для выбранного сценария отправляет конфигурацию контроллера в `POST /api/simulate`.
3. Backend проходит наблюдения по секундам, выбирает фазы, формирует события и сводную статистику.
4. Для видеоэпизода наблюдения загружаются из связанного JSON, а запись отдаётся через `GET /api/videos/{scenario_id}`.
5. FastAPI также раздаёт готовую frontend-сборку, поэтому для локального просмотра достаточно запустить один сервер.

### Логика контроллера

Цикл фаз проходит в фиксированном безопасном порядке: `vehicle_green` → `warning` → `all_red_to_ped` → `pedestrian_green` → `all_red_to_vehicle` → снова `vehicle_green`. В адаптивном режиме контроллер не завершает минимальную автомобильную фазу досрочно. При ожидающем запросе он рассматривает переход, когда дорога свободна в течение пяти секунд, поток ниже порога, достигнут предел ожидания или ожидает достаточно большая группа. Запрос остаётся активным до обслуживания пешеходной фазой.

При потере наблюдений используется резервный фиксированный цикл; неизвестные показатели не трактуются как нулевые. В ручном режиме применяются заданные длительности фаз. Фиксированный сценарий сравнения использует 30-секундную автомобильную фазу и 12-секундную пешеходную.

На видео пешеходный запрос сейчас определяется по переходу `waiting` из нуля в положительное значение. Формат наблюдений не содержит идентификаторов отдельных людей, поэтому точный учёт уникальных запросов ограничен имеющимися данными.

## Быстрый запуск

Из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate        # Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r backend/requirements.txt
npm --prefix frontend ci
npm --prefix frontend run build
python -m uvicorn backend.app.main:app --reload
```

Откройте <http://127.0.0.1:8000>. Документация API доступна на <http://127.0.0.1:8000/docs>, проверка доступности — <http://127.0.0.1:8000/api/health>.

### Интерактивный симулятор

Откройте вкладку «Симулятор», выберите «Свой поток» и задайте интенсивность машин и пешеходов, время суток и тип дня. Время и тип дня меняют расчётный спрос, а время суток также меняет освещение карты. Можно выбрать и готовый сценарий; изменение параметров потока переключит обратно на пользовательский. Выберите режим управления. В ручном режиме можно изменять длительность каждой из пяти фаз; в адаптивном — минимальную автомобильную и пешеходную фазы. Изменения автоматически отправляются в `POST /api/simulate`; сцена, сигналы, шкала и показатели обновляются по одному ответу модели. Перемотка, пауза, повтор и скорость помогают сравнивать моменты. Карта построена в Three.js: объёмный перекрёсток с четырьмя пешеходными переходами, машинами, встречными потоками людей и отдельными автомобильными и пешеходными светофорами на обеих сторонах каждого перехода. Сцену можно вращать и приближать мышью. Поступления участников соответствуют расчёту сценария, движение по дороге и ожидание у перехода показаны схематично; это не микроскопическая транспортная модель.

### Разработка интерфейса

В одном терминале запустите API:

```bash

```

Во втором:

```bash

```

Откройте адрес, указанный Vite (обычно <http://127.0.0.1:5173>). Vite перенаправляет запросы `/api` на локальный backend.

## API

### `GET /api/health`

Проверка: `{"status":"ok","source":"cv-json-and-simulation"}`.

### `GET /api/scenarios`

Возвращает `id`, название, описание, длительность и визуальный тип каждого сценария.

### `POST /api/simulate`

Пример запроса:

```json
{
  "scenario_id": "video",
  "config": {
    "control_mode": "adaptive",
    "min_vehicle_green": 10,
    "low_flow_threshold": 24,
    "group_threshold": 5,
    "max_single_wait": 20,
    "max_group_wait": 15,
    "pedestrian_green": 8
  }
}
```

`scenario_id` принимает `video`, `normal`, `rush`, `group`, `empty`, `failure` или `custom`. Для `custom` передайте `profile` с `vehicle_rate` (0–90 авто/мин), `pedestrian_rate` (0–30 чел./мин), `time_of_day` (`morning`, `day`, `evening`, `night`) и `day_type` (`weekday`, `weekend`, `holiday`). По умолчанию используются 18 авто/мин, 6 чел./мин, день и будний день; эпизод длится 120 секунд. Ответ дополнительно содержит `profile.effective_vehicle_rate` и `profile.effective_pedestrian_rate` после поправки на условия. Валидация длительностей фаз действует и для пользовательского сценария. Режим `control_mode` — `adaptive` или `manual`; для ручного режима можно передать `phase_plan` с длительностями фаз. Ответ содержит покадровые результаты `frames`, журнал `events`, сводку `summary`, а для видео-сценария — также результаты фиксированного цикла `baseline` и моделируемую разницу ожидания `modeled_wait_difference`.

### `GET /api/videos/{scenario_id}`

Возвращает MP4 выбранного заранее подготовленного видеоэпизода. Текущая запись доступна по `/api/videos/video`. Старый адрес `/api/video` сохранён для совместимости.

## Данные видео и CV

Файл `video_and_json/result_crosswalk.json` содержит 162 наблюдения — по одному на секунду новой записи. Формат и значения полей описаны в [CV_DATA_FORMAT.md](CV_DATA_FORMAT.md).

Чтобы подключить другой эпизод, подготовьте MP4 и JSON по этому контракту, положите их в корень проекта и добавьте одну запись в `VIDEO_EPISODES` внутри `backend/app/video_episode.py`. Backend автоматически включит эпизод в каталог API, а frontend возьмёт его `video_url`. Загрузчик файлов для этого не требуется.

Сравнение циклов на готовой записи является модельной оценкой: поведение людей и транспорта в исходном видео уже зависело от реального светофора. Поэтому результат показывает повторное воспроизведение наблюдений и решения виртуального контроллера, а не измеренный эффект на реальном объекте.

## Участие в разработке

1. Создайте ветку от `main` для своей задачи.
2. Установите зависимости и запустите приложение по инструкции выше.
3. Перед pull request проверьте backend-тесты и production-сборку frontend.
4. В описании pull request укажите, что изменилось, как это проверено и затрагивает ли изменение модель фаз или формат CV-данных.

Изменения контракта наблюдений необходимо отражать в `CV_DATA_FORMAT.md` и валидаторе в `backend/app/video_episode.py`.

## Ограничения и дальнейшие шаги

- Управление и светофор виртуальные; реальное оборудование и камеры не подключены.
- Наблюдения в демонстрационном JSON оценочные, метрики — иллюстративные.
- Доступность проезда показывает долю автомобильной зелёной фазы, но не заменяет модель задержки транспорта.
- Пороговые значения и фазы требуют инженерной, транспортной и нормативной валидации для конкретного перекрёстка.
- Следующие направления: подключение результатов CV-команды, валидация данных, отдельные сценарии отказа и проверка модели с профильными специалистами.
